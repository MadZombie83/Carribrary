# Release requirements

The maintained product/engineering specification and current repair scope are in
[CARRIBRARY-MASTER.md](../CARRIBRARY-MASTER.md), including administrator authentication
amendment 3.1. Record future owner requirements and status changes there.

Every user-visible feature, change of behavior, setting, permission or workflow must
include corresponding help changes in the same release. This is a project requirement.

1. Update the canonical `assets/help.json` topics and its `release` value. Explain
   the actual buttons/locations, effects, limitations and relevant recovery steps.
2. Run `python3 scripts/sync-help.py` from this source checkout to synchronize the
   server, offline Android/iPhone help and versioned standalone Markdown guide.
3. Run `python3 scripts/sync-help.py --check` before packaging. Rebuild every affected
   platform after synchronizing assets; do not ship stale help in an installer.
4. Update README, release/update instructions, privacy documents when applicable,
   and the borrower browser's own account Help when its behavior changes.
5. Validate server/model/browser flows, Android build/lint/signing and package
   contents. iPhone source needs Mac/Xcode/device validation before distribution.

Never include runtime databases, keyrings, signing keys, real sending credentials
or private backups in a source or application package. Do not edit synced `sources/`.

## Local administrator authentication boundary (2.0.33)

Local dashboard/API access now requires a valid local session or approved companion
credential. Do not reintroduce port-only administrator authorization. Browser proxy
requests forward the existing paired token and revalidate it at the local API;
Android continues per-request certificate approval. Never put a shared bypass key
in the proxy. Local setup requires private filesystem proof, and recovery cannot
write while the credential store is open. Session/recovery data are independent
of borrower credentials and private reading vaults.

Health checks use `/local-auth/health` (readiness/version only), not anonymous
administrative API reads. Windows automatic program recovery is restricted to
2.0.33 because older binaries would remove local login. The older cohort notes
below are historical. Library format stays 3. Source repair and focused tests are
recorded in `the prior repair report (maintained privately)`; 2.0.33 preview packages have been built and checked in the prior validation report (maintained privately).
Physical Windows service/ACL and installation checks remain required before production release.

## Recovery compatibility gate (2.0.28)

Recovery.Core.ps1 now permits only the 2.0.29 cohort, retaining CURRENT data. Earlier 2.0.27/2.0.28 compatibility was superseded by the format-2 boundary. Future schema/privacy changes must revisit that
cohort before shipping; never extend it merely to pass a version check. Windows
recovery uses administrator-protected registry manifest seals, protected snapshot
storage and an exclusive maintenance mutex. Do not grant LocalService write
access to program recovery points or seal metadata. Preserve trust metadata on
uninstall while retaining private snapshots. Recovery-attempt archives are safety
copies, not known-good candidates. No historical data restore is exposed.

Before NSIS, run scripts/package-manifest.py after final Windows server/tray
publishing. Run tests/recovery-core.ps1 and tests/parse-powershell.ps1 using
PowerShell, then test elevation, service/ACL/registry integration and installer
failure recovery on Windows. Linux core/fault tests do not certify that runtime.

Quick-start screenshots are generated by tests/quick-start-ui.mjs only through
the disposable fixture harness. Never capture a user's live catalog. Review
images and run guide/browser checks after publishing them. PNG masthead artwork
and built-in pattern work is queued in the private roadmap.

## Permanent copy identity format boundary (2.0.29)

Library format 2 adds Book.copyUid. UpgradeCopyIdentity creates a private administrative pre-migration backup and commits once in a transaction. New records get fresh UUIDs; edits and recycle/backup restore preserve them. Old format-1 imports receive missing identities. Invalid duplicates are rejected. UI catalog numbers and current operational BK references are preserved. Earlier servers reject format 2; Windows recovery is restricted to 2.0.29. Keep full stopped-server backups for cross-format recovery.

Build/test processes must use disposable directories. Do not purge the installed Flatpak or remove its lock/data during package builds. Keep the early-version upgrade → clean stop → complete purge → fresh setup scenario in physical-install testing.

## Complete data snapshots (2.0.30)

All normal HTTP operations take a SnapshotGate shared lease through response headers (all current mutations finish before headers); responses release before slow client downloads. The companion proxy outer request is excluded to avoid nested writer deadlock; its authenticated local API request takes the lease. Full snapshot endpoints authenticate normally, then acquire an exclusive lease. Background backup/reminder/push jobs take shared leases. Future writers, lazy disk-backed services or streaming mutation handlers MUST participate in this gate. Keep all writes before response headers or hold an explicit lease. Consistency assumes no independent external process is editing the same data directory.

Complete archive recovery is offline and only unpacks into a new folder, with authenticated streaming decryption, bounded ZIP/inventory validation, hashes and SQLite checks. Do not add live full-data replacement without scoped authorization, shutdown coordination and historical-credential/deletion warnings. Secret-bearing temporary/recovered folders must remain owner/admin-only. Plaintext legacy borrower reading is blocked rather than exported to admins.

2.0.31 copy-label invariant: machine-readable labels use `carribrary:copy:v1:<CopyUid>`; never fall back to the displayed BK code for unknown/malformed/stale references. Both individual and batch circulation filter eligible copies before selection. Allocation policy is persisted with the high-water counter in library format 3; older program recovery is not compatible. Preserve every existing CopyUid during format-2 migration.

## Administrator accounts and artwork (2.0.36)

Owner explicitly requested removal of hardcoded sidebar artwork and multiple dashboard sign-ins. Optional bounded PNG artwork is an additive LibraryState property, default empty, saved through the existing action/revision/backup system. Credential format 2 uses the existing protected file and keyring but a v2 protection purpose; v1 is only read for safe atomic migration. Original primary password/recovery/setup hashes are preserved. New sessions bind to stable administrator IDs and recheck existence; password reset/removal invalidates only target sessions. Primary proof recovery retains global local-session invalidation. All dashboard accounts are full trusted administrators; primary/current removal is protected. Independent approved-device identities are not linked or revoked by local-account removal. Old programs fail closed on the new credentials; automatic program recovery cohort is 2.0.36 only. No public username/password admin route is added. Source-only owner build remains in force.
