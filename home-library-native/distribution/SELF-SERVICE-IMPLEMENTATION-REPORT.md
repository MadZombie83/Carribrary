# Self-service implementation report — 2.0.53 preview

Validation status is recorded below. This is source for owner builds, not an installed release or a public-release approval.

1. **Functionality:** independent opt-in self-checkout, pending self-return and kiosk enablement; physical/digital library cards; issue/replace/revoke/PIN reset; batch/single branded PDF/printing; restricted station provisioning and revocation; native Android administration and librarian card scanning.
2. **Reuse:** Store SQLite locking/idempotency, Library/CirculationPolicy holds/limits/checkout/final return, existing account approval/linking, permanent CopyUid QR, camera/default focus and bundled ZXing, native ML Kit, QR generator, theme/art/icon assets, notification bell, complete snapshot/recovery and synchronized Help.
3. **Migration:** format 7 adds permanent BorrowerUid, SelfService settings and loan source/pending-return fields. Existing borrowers receive UUIDs without changing BR display IDs. Recycle restoration preserves UUIDs; a reused display number cannot inherit a deleted borrower’s card. Physical copy identities and paired-device protocols remain unchanged. Protected pre-upgrade snapshot and older program rollback guard are included.
4. **Settings:** checkout/return/kiosk default OFF independently; loan days 1–365 (14 default); station idle timeout 30–300 seconds (90 default); return instructions up to 1000 characters. Station pairing codes expire after 10 minutes; authorized station cookies after 30 days. No automatic public exposure or router configuration.
5. **Security:** account identity is server-derived inside active-account validation; optional JSON identity cannot choose another borrower. Card QR is a random identifier, not login or vault credentials. PINs use salted 210,000-iteration password hashes inside the protected registry; five failures lock verification for 15 minutes, in addition to endpoint rate limits. Station and borrower cookies are distinct Secure/HttpOnly/SameSite Strict cookies. Every operation checks policy, station, current card, borrower UUID, PIN generation and idle expiry. Revoke/reset takes effect on subsequent requests, including live sessions. Registry is initialized during recovery startup before access may resume. No vault or full borrower database is sent to kiosk clients.
6. **Cards/printing/scanning:** server/companion browser uses real QR SVG, CR80 CSS geometry and browser Save as PDF; Android uses a native PDF with exact 243×153-point card geometry. Letter/A4 batch eight per sheet, optional long-edge duplex and cut guides. Logos preserve proportions, art crops without stretching, and names size down with a bounded truncation fallback for extreme physical-space limits. Borrower screens, settings tools and normal checkout expose cards; manual borrower lookup remains. Camera and typed/USB identifiers are supported; actual hardware validation is outstanding.
7. **Borrower PWA:** active linked account is required for self-service. Existing ISBN/EAN, optional copy QR, BK/title entry can locate eligible copies; ambiguous ISBN matches require a physical-copy choice. Checkout is atomic with normal limits/holds and source audit. Own return report stays active/unavailable and appears in My loans; librarian final return confirms custody. The same valid issued card appears under Account. Reading-vault encryption is independent.
8. **Kiosk:** standalone focused browser page at the same public HTTPS server /kiosk/ URL; no second server. Named one-use provisioning, card+PIN verification, eligible-copy confirmation, keyboard/touch controls, camera/manual scanning, cancel/error/idle cleanup, brief receipt and automatic screen reset. One transport retry reuses the transaction ID after a lost confirmation reply; a second failure directs the borrower to the librarian. Browser station credentials expire/revoke independently of admin pairing. Browser fullscreen and OS lockdown are separate responsibilities.
9. **Windows/Linux compatibility:** real headless Chrome/Linux browser workflows and Linux .NET tests run in disposable data. A real 2.0.52→2.0.53 upgrade test preserves local admin credentials, catalog, active loan, household reading, saved palette/art, sharing link, native TLS identity and paired browser/phone access; older software rejects the upgraded format. Windows binaries, Edge Assigned Access, Linux kiosk session lockdown, physical phone cameras and Pi hardware are not independently executed here.
10. **Backup/recovery:** actual complete capture/unpack tests include cards, PIN registry, revocations, permanent IDs and settings. Restored active cards require deliberate review; all station credentials are revoked. Known local revocation tombstones merge during replacement. Unknown later revocations cannot be inferred from an old backup on another machine. Library-only backup does not restore card/PIN/device credentials. Existing complete recovery workflows remain and pre-migration backups are private.
11. **Automated results:** .NET build (zero warnings/errors), all native server/model/security tests, synchronized Help, recovery PowerShell core, Android release Kotlin compile and iOS source reference/plist checks pass. New browser acceptance covers PWA checkout/pending return, kiosk enrollment/verification/checkout, keyboard scanner behavior, immediate live-card revocation, restricted endpoints, all-off API rejection, PDF generation and decoding the actual card QR. Wider browser regression completion is recorded in VALIDATION-2.0.53.md. Browser PDF page geometry measured 242.88×153.12 points (Chrome rounding within 0.05 mm of CR80); native geometry is 243×153 points.
12. **Manual tests:** physical printed/laminated cards, paper margins/duplex, actual QR-capable USB scanner/webcam, physical Android/iPhone PWA cameras, separate Windows Edge and Linux kiosks, OS lockdown/escape prevention, browser restart persistence, new installer upgrades and actual replacement-machine restore. No unexecuted case is claimed as passing.
13. **Limitations:** no offline kiosk circulation; no OS-lockdown installer; trusted HTTPS and running server required. Edge kiosk/private-browser resets may remove station cookies and require reprovisioning. Long physical-card text has readable-size/layout limits. A 1D-only scanner cannot read QR. Trust-based self-checkout cannot establish physical possession from a copied barcode. Kiosk audit captures successful circulation source/station and pending-return history; failed verification errors remain generic and do not create an identifying borrower activity feed.
14. **Release blockers:** implementation is a preview pending the owner hardware/package/accessibility acceptance above and the remaining full regression evidence. Do not mark the product feature-complete for the initial public candidate until practical scenarios A–H have been validated. No release installers, signing credentials, personal emails or runtime library data are distributed with this source.
