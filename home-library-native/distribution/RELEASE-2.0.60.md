# Carribrary 2.0.60 preview — Libraries & network and household reader app

Settings & Tools → System & Advanced → Libraries & network now guides independent libraries on one computer and encrypted connections from another computer through a single managed public HTTPS entry. Existing books, pairing protocols and the primary localhost cookie name remain intact. Each additional library has separate ports, data, administrator credentials, pairing identities and backups. Start/pause controls keep its data. Windows has a review-and-apply hosting assistant with Start-menu access, machine-key preparation, scoped firewall rules and legacy Carribrary proxy migration/undo. Flatpak and Pi keep unprivileged public ports; router settings remain user-controlled.

Each public library uses a distinct hostname. The first public entry keeps the existing library route. Other computers use an explicit private credential file, pinned TLS certificate and an authenticated bridge to their public listener only. Native Android retains its existing secure connection and separate per-library phone-port rule. Optional per-hostname DuckDNS updates keep tokens protected at rest. Recovery rehearsal/review blocks automatic hosting activation. Missing initialized child databases never silently become empty libraries.

Household readers can install their personal reading page through **This device → Install reader app**, using the shared PWA install controller, library icon and a separate reader app identity. The private capability stays out of the manifest. Remembering it on the device is optional and off by default, with a Forget action. iPhone storage isolation has paste-the-private-link fallback. Private reading content is not cached offline. Borrower installation, native Android installation and librarian pairing remain separate.

Owner-built 2.0.60-preview Windows EXE, Linux x86_64 Flatpak and Pi ARM64 DEB installers are now published at https://github.com/MadZombie83/Carribrary/releases/tag/v2.0.60-preview with SHA256SUMS.txt. All three were extracted and inspected without installation/execution: embedded version, Help, license, critical web assets and Windows hosting helper match the audited source; no known owner-email, credential or private-runtime findings. No Android APK/AAB is distributed. Preview acceptance still needs actual Windows hosting assistant/service/firewall tests, Pi service tests and physical iPhone Home-screen installation. Do not mistake automated Linux/Chrome checks for those device tests.

Additional-library recovery boundary: portable archives can move an extra library into a fresh independent installation on a replacement computer. The installed complete-recovery shortcut still targets the main installation. In-place complete recovery into a managed additional-library slot currently needs assisted recovery; its dashboard explains this and does not open the main recovery shortcut. Back up every library separately. No additional-library data is included implicitly in a parent backup.
