# Carribrary 2.0.49 preview — admin notifications and web-app installation

The server dashboard, paired iPhone/browser companion and native Android now share a notification inbox. The bell counts account approvals, borrowing requests, renewal requests, holds awaiting handover, overdue active loans, restored-access review and reported backup/email/push problems. Review opens the existing tool; opening an item does not dismiss it. Resolved conditions clear after refresh. Count summaries never inspect encrypted borrower reading records or expose contact details.

The server/PWA checks about every 15 seconds when no form is open and on focus. Android checks every 30 seconds while in the foreground, on opening/closing tools and after library changes; its optional background alerts remain periodic, not instant. Unavailable checks retain the last list with a warning. Optional web push also recognizes new account and renewal requests alongside book requests; enabling it starts with a baseline rather than notifying for existing requests.

The public welcome page now includes the borrower manifest and installation control. Account, companion and shared catalog paths without a trailing slash redirect to their canonical page so relative assets resolve correctly. The librarian pairing page and paired Settings & Tools → People & Access offer installation controls. Borrower and librarian identities stay distinct and stable; manifests never disclose catalog tokens. Chrome's native install prompt is used when available, with clear HTTPS/trusted-certificate, regular-browser and already-installed guidance otherwise. iPhone uses Safari's Add to Home Screen. No browser data clearing or unpairing is needed to receive server changes. A shortcut alone is not confirmation of app installation.

Install a freshly owner-built **server package and Android APK** over the existing installation; do not uninstall or delete data. Refresh open browser tabs. No release installers or APKs were built by the coding agent. Library/credential formats remain **6/2**; supported program recovery cohort **2.0.47–2.0.49**. Save a complete portable backup off the server and keep its password separately before updating.

Chrome installability, decoded icons, scoped service workers, canonical routes, authorization and real notification decisions are covered by browser/server regressions. Headless tests do not prove physical Android WebAPK or iPhone Home-screen installation, which still need owner verification. Raspberry Pi ARM64 remains experimental and untested on physical hardware; no Pi is currently available to the owner.
