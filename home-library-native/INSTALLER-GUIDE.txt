CARRIBRARY 2.0.54 — INSTALL, CONNECT AND UPDATE
Developer: Chezburber Studios. Support: chezburbermerch@gmail.com.


1. PICK THE RIGHT FILE
Download the server installer from the official GitHub Releases page:
https://github.com/MadZombie83/Carribrary/releases
Choose the release recommended by Chezburber Studios.
The server is free. Windows uses the EXE installer. An Intel/AMD Linux desktop uses the x86_64
Flatpak. A Pi 4/5 with 64-bit Pi OS uses the ARM64 DEB. The optional Android librarian companion
is a separate Google Play purchase when the listing is live. Borrowers pay nothing.
You do not need source code or build tools for normal installation.
Do not install the Pi DEB on an Intel/AMD Kubuntu laptop.

2. INSTALL ON WINDOWS
1) Open Carribrary-Setup-2.0.54-preview.exe on the server computer.
2) Approve the Windows administrator prompt and follow setup.
3) Open Carribrary from the desktop or Start menu.
4) Follow first administrator setup. Use the private setup file path shown on
   the page, or Start > Carribrary > Administrator access to copy its code.
5) Choose a username/password and save the recovery code privately off this PC.
6) Sign in. You should see Dashboard at http://localhost:4173.

Installed server packages include their .NET runtime. Node.js is not needed.
The Windows service starts in the background. Closing the browser/tray does not
stop it. Keep the computer awake when phones or borrowers need the library.
The local administrator must sign in even when Windows is already signed in.

3. ADD THE OPTIONAL ANDROID LIBRARIAN APP
1) Open Google Play and find Carribrary by Chezburber Studios.
2) Check availability and local pricing, then purchase/install the companion.
   Use the official Carribrary release page to confirm download availability.
3) Put phone and server on the same home network for the first local test.
4) In server Help, follow Pair the optional Android librarian companion.
5) Use People & Access > Android phone pairing to make the PRIVATE pairing QR.
6) Scan it in the Android app, then Refresh and check Connected.

For updates, open Google Play and choose Update when offered. Never
uninstall/clear app storage just to update. Revoke lost phones on the server.
Borrowers do not need this librarian app or its QR.

4. ADD THE IPHONE/BROWSER LIBRARIAN APP
1) Finish public trusted HTTPS setup using the connection topics in Help.
2) On iPhone open https://YOUR-HOST/companion/ in Safari.
3) Use Share > Add to Home Screen; open that icon before pairing when possible.
4) In server People & Access > iPhone / browser pairing, create a private code.
5) Enter it, name the device and pair within ten minutes.
6) Check Refresh. Revoke or pair again after expiry as needed.

This PWA is a browser app hosted by your server. Install it using Safari. The
separate native Swift project is unverified without Mac/Xcode and is not the
normal iPhone installation route. Safari and installed apps may use different
storage, so do not assume pairing in Safari also pairs a Home-screen app.

5. BORROWER ACCESS
1) Configure public HTTPS and test the hostname from mobile data with Wi-Fi OFF.
2) Choose Share Library in Quick Actions and enable/copy the library link or QR.
3) Give THAT link to borrowers, not a private librarian pairing code.
4) Borrowers can browse, request and suggest acquisitions without accounts.
5) Optional accounts need approval and a verified borrower link. They add private
   TBR/reading/wishlists and own loan/request management.

The plain public address shows a welcome page. It does not expose the private
catalog link and has no install button. Borrowers install from the shared
catalog or Account > This device; Chrome controls whether Install is offered.
On iPhone use Safari > Share > Add to Home Screen. A shortcut alone is not full
app installation. Browser apps need a reachable server; they do not cache private
catalog/API records for offline circulation.

6. REMOTE CONNECTION
Windows: Start > Carribrary > Connection setup. Create a hostname at
https://www.duckdns.org/ if needed. Save the full hostname and optional private
DuckDNS token. Set up public book-list sharing for borrower/iPhone/kiosk pages.
Follow the displayed router instructions. Windows normally uses TCP 7443 for
native Android and TCP 80/443 for public HTTPS.

Linux/Flatpak/Pi: see linux/README.md. Its managed public HTTPS setup uses router
TCP 80 -> server 8080 and TCP 443 -> server 8443. These are NOT the Windows rules.

Never forward 4173, 4174 or 7445. DuckDNS names your internet address; it does not
supply HTTPS or configure a router. Carribrary can update DuckDNS without another
DuckDNS app. Check DNS, router, firewall and provider restrictions if mobile data
fails. Do not bypass certificate errors. Test outside access before inviting
borrowers. Advanced existing proxies use ADVANCED-OPERATIONS.md.

7. UPDATE WITHOUT LOSING DATA
1) Make and verify a COMPLETE .carribrary-backup, save it off this computer and
   keep its password separately. Library JSON is not a full recovery backup.
2) Run the new installer over the existing Windows installation. Do not uninstall
   or delete app data. Close a leftover manual server if it occupies the port.
3) Update Android through Google Play. Refresh browser apps.
4) Check books, borrowers, loans, appearance and paired devices.

2.0.54 uses library format 7 and credential format 2. Older executables cannot
preserve the current data. Windows Update and recovery restores only compatible
PROGRAM files (currently 2.0.54) while keeping current data. Complete Backup
Recovery restores historical DATA after verification, testing and confirmation.
Do not confuse the two or force an older program to open upgraded data.

8. RECOVER OR REPLACE THE COMPUTER
1) Install matching compatible Carribrary on the destination.
2) Open Complete Backup Recovery from Start or the Linux/Pi application menu.
3) Choose the portable complete archive, enter its password and verify it.
4) Start recovery test; check the separate RECOVERY TEST copy in a private window.
5) Follow the confirmed Restore library steps. Current data is retained first.
6) Review restored accounts/devices locally before resuming remote access.
7) Review restored cards and authorize fresh kiosk stations. Set up networking,
   HTTPS helpers and paused message/backup schedules deliberately.

Do not run two servers with one restored identity. Legacy machine-bound Windows
archives need their original computer; new portable complete backups support a
replacement. Backup passwords and private-reading recovery secrets cannot be
reset by the developer. Keep retained recovery folders private.

9. WHEN SOMETHING GOES WRONG
Use Help > Troubleshooting and the installed diagnostics. Keep the exact error
and version. Do not delete databases or credential files. Review diagnostic text
before sharing it. Never send keys, tokens, signing files, private QR/reset links
or backup files to support.

New self-checkout, self-return reports and kiosks start OFF. Follow their Help
steps if you enable them. A self-return is not final until a librarian confirms
the physical book.
