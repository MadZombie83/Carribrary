CARRIBRARY 2.0.53 — START HERE
Documentation reviewed 2026-10-30. Features are frozen; release testing continues.

DO YOU HAVE SOURCE OR AN INSTALLER?
A source ZIP is for building. Extract it into a NEW empty work folder, then open
home-library-native/BUILD-LOCALLY.md. Never merge it into old source or installed
server folders. This documentation update does not generate installers for you.

For installation, use the matching package:
- Windows: Carribrary-Setup-2.0.53-preview.exe
- Intel/AMD Linux desktop: Carribrary-Linux-x86_64-2.0.53-preview.flatpak
- Pi 4/5 with 64-bit Pi OS: Carribrary-Pi-ARM64-2.0.53-preview.deb
- Android librarian: matching signed APK, or the approved Play listing when live
- iPhone librarian: the server's /companion/ browser app, not an APK

FIRST SETUP
1. Install the server package on the computer that will keep the library.
2. Open Carribrary there. The local page is http://localhost:4173.
3. Follow administrator setup using the private code at the displayed file path.
   Windows Start > Carribrary > Administrator access can copy the existing code.
4. Save your recovery code privately, away from this computer.
5. Add one book, add a borrower if needed, then test checkout and return.
6. Make and verify a COMPLETE password-encrypted backup. Copy it off this drive.

The server works without public sharing, companions, accounts or Google Books.
Keep it running and awake when people need it. Borrowers need only the sharing
link for ordinary browsing/requests. Accounts add optional private TBR/reading.

UPDATING
1. Make a complete backup and keep its password separately.
2. Install over the old server/app without uninstalling or clearing data.
3. Update Android with the same signing identity. Only the APK goes on the phone;
   private signing folders and passwords never do.
4. Refresh browser apps and check the library.

Current data format is 7, credentials 2. Program rollback to older releases is
blocked. Complete Backup Recovery is a different tool: verify, test a separate
copy, confirm restoration, then review local access before remote use resumes.
Use a portable complete archive for a replacement computer, not library JSON.
